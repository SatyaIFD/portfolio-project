# ADR 005: Zero-Skew FastAPI Serving, Fail-Closed Artifact Verification & Multi-Stage Non-Root Docker

- **Status:** Accepted
- **Date:** 2026-11-25
- **Context:** Phase 3 requires exposing the trained claims triage pipeline over HTTP for Cloud Run (`GET /health`, `POST /predict`) with zero training-serving skew, strict zero-PII enforcement, cryptographic verification of mounted model artifacts before deserialization, and a compressed container footprint comfortably below Artifact Registry's 0.5 GB Always Free Tier limit.
- **Decision:**
  1. Refactor `src/claims_triage/schemas.py` so `ClaimRecord` inherits from an 8-feature `ClaimInput` base model (`ConfigDict(extra="forbid")`) and route both Phase 2 training and Phase 3 online inference through a shared `inputs_to_feature_matrix()` helper, structurally eliminating training-serving skew while rejecting leaked target labels (`is_exception`) and unexpected PII fields with `HTTP 422`.
  2. Implement `src/claims_triage/api.py` using an isolated `create_app()` factory and FastAPI `lifespan` hook that loads models exclusively through `load_verified_artifact()` (enforcing path-traversal containment and constant-time SHA-256 verification before `joblib.load()`). If artifacts are missing or tampered with, the service fails closed by returning `HTTP 503` on both `/health` and `/predict` rather than crashing or serving unverified binaries.
  3. Emit single-line, zero-PII JSON telemetry (`model_artifact_loaded`, `prediction_served` with bucket, probability, and latency only) formatted via `%(message)s` for native Google Cloud Logging `jsonPayload` ingestion, exposing only a 12-character SHA-256 prefix on `/health`.
  4. Package the service in a two-stage `python:3.13-slim` `Dockerfile` installing only locked production dependencies (`fastapi` + pure-Python `uvicorn`, excluding dev/test tools and `uv`) into `/app/.venv`, stripping unneeded base-image `pip` and `ensurepip` packaging artifacts from the runtime stage (see Hurdle 004), running as non-root `uid=10001` (`appuser`) with `exec uvicorn` as PID 1 honoring `${PORT:-8080}` for graceful Cloud Run `SIGTERM` handling, a stdlib `urllib` `HEALTHCHECK` (no `curl` bloat), and read-only (`:ro`) artifact mounting.
  5. Enforce automated container builds, `uid=10001` verification, and Trivy `HIGH,CRITICAL` (`ignore-unfixed: true`) image scanning inside the required GitHub Actions `security-and-quality` CI job.
- **Consequences:** Local container verification confirmed `122.5 MB` gzip-compressed size (`554 MB` uncompressed, leaving room for multiple retained tags within Artifact Registry's 0.5 GB free tier), `4.5 ms` warm prediction latency (`128 ms` first-request warm-up), `98.01%` test coverage (`34/34` tests), and full fail-closed and PII-rejection guarantees. Trades away C-extension `uvicorn[standard]` extras (`uvloop`/`httptools`), which are unnecessary at Cloud Run's low-concurrency free-tier scale.
